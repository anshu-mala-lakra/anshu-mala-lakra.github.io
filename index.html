06 — Case studies

The interesting part is what happened underneath.

Open a blueprint when you want the longer version: what was wrong, what changed, and what the result taught me.

01

Quarterly SOA Batch Pipeline

+
Problem

Quarterly SOA batch processing required 12+ hours.

Context

Account statements needed to be generated and delivered on time across the customer base.

Thinking

The work was dominated by sequential execution, so the pipeline needed end-to-end redesign rather than small local tuning.

Implementation

Used parallel processing and multi-threaded execution across .NET, C#, Oracle, and PL/SQL.

Result

Runtime moved from 12+ hours to under 3 minutes, a 99.6% reduction.

Learned

Performance work starts with finding the real bottleneck, not decorating the slow path.

02

CoreNx System Health Reporter

+
Problem

Stakeholder reporting depended on legacy SSRS infrastructure.

Context

Operational visibility was needed at 30-minute and 1-hour intervals.

Thinking

An in-house reporter could reduce infrastructure dependency while making reporting more controllable.

Implementation

Built a .NET Core System Health Reporter with automated schedules.

Result

Automated 21 stakeholder reports and reduced long-term infrastructure and operational costs.

Learned

Modernization is strongest when it removes a dependency and improves daily operations at the same time.

03

Letter Generation API

+
Problem

Different document workflows needed different security behavior.

Context

Customers received password-encrypted email attachments while authenticated branch users needed unencrypted ZIP exports for dispatch.

Thinking

Security needed to follow context, not apply the same friction to every workflow.

Implementation

Implemented context-aware document handling in an ASP.NET Core REST API.

Result

Reduced manual per-file decryption overhead for physical dispatch operations.

Learned

A secure system still has to respect the shape of real operations.

04

Unposted Transaction Clearance

+
Problem

Loan foreclosure or termination required checks against unposted transaction states.

Context

Ten transaction types, including receipts, pay-in slips, ARAP, and EFT, needed validation.

Thinking

A maker-checker workflow would preserve control around a critical loan lifecycle gateway.

Implementation

Built validation and approval flow before permitting foreclosure or termination.

Result

Improved data integrity at a sensitive business checkpoint.

Learned

Business rules are architecture when money, auditability, and state transitions meet.

05

Loan Disbursement Data Integrity

+
Problem

Concurrent sessions and double submissions generated duplicate records.

Context

Duplicate records affected loan disbursement data integrity.

Thinking

The fix needed session isolation, validation, and database-level protection.

Implementation

Used ViewState-based session isolation, frontend sum validation, and rowID-tied idempotency constraints.

Result

Prevented duplicate records caused by concurrent use and repeated submissions.

Learned

Data integrity should not depend on the user clicking perfectly.

06

70+ AppSec Vulnerability Remediation

+
Problem

A third-party security audit identified 70+ vulnerabilities.

Context

The application handled enterprise banking workflows and needed a hardened posture.

Thinking

Remediation had to cover application, configuration, infrastructure, and request-handling surfaces.

Implementation

Worked on TLS cipher hardening, encrypted secrets, infrastructure hardening, input validation, rate limiting, malicious-request filtering, and error-page redirection.

Result

Closed 70+ AppSec findings from the audit.

Learned

Security is not one fix. It is a series of smaller disciplined boundaries.

07

Azure DevOps CD Recovery

+
Problem

Two critical CD pipeline failures caused repeated retries and deployment delays.

Context

IIS deployments needed to work with enterprise PAM credential rotation.

Thinking

The pipeline needed predictable app-pool control and credential fetching aligned with the enterprise environment.

Implementation

Added automated IIS app-pool stop/start scripts and PAM-aligned credential fetching.

Result

Deployments moved from 15+ minutes with repeated retries to consistent 7-8 minute runs.

Learned

Deployment reliability is product reliability wearing an operations jacket.
